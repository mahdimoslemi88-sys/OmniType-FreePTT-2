# موتور «Antigravity Live Dictation» — پیاده‌سازی‌شده در voice-ptt

**تاریخ:** ۲۷ سپتامبر ۲۰۲۶ · **وضعیت:** پیاده‌شده، تست‌شدهٔ انتها-به-انتها، در بیلد ریلیز

---

## ۱. در یک نگاه

```
[نگه‌داشتن CapsLock]  →  ضبط محلی (همان مسیر فعلی، PCM 16kHz)
        ↓  (رها کردن کلید)
AntigravityEngine::transcribe(utterance)
        ↓  ۱. کشف زبان‌سرور:  PID زبان‌سرور → پورت → توکن CSRF
        ↓  ۲. StreamAudioTranscription  (gRPC-Web + JSON روی loopback)
        ↓  ۳. ready{sessionId}  →  SendAudioChunk × N (base64 PCM16، ۴۰ms هر chunk)
        ↓  ۴. EndAudioSession  →  transcription{…, isFinal} + complete
        ↓
متن نهایی → نرمال‌سازی فارسی → تایپ در پنجرهٔ هدف
```

هیچ کلید API و هیچ حساب ابریِ **ما** در کار نیست: سرور محلی خودش توکن گوگل را
دارد و صدا فقط تا `127.0.0.1` می‌رود. (جزئیات پروتکل:
[`Antigravity-Log-Analysis-02.md`](Antigravity-Log-Analysis-02.md).)

تنظیمات:

```toml
[antigravity]
enabled = true            # ثبت موتور
cascade_id = ""           # خالی = خودکار از پنجرهٔ باز Antigravity خوانده می‌شود
ready_timeout_secs = 30   # سرور محلی ~۱۳s طول می‌کشد تا سشن را باز کند
finalize_timeout_secs = 12
```

## ۳. یافته‌های اندازه‌گیری‌شده (همه روی همین دستگاه)

### ۳.۱ کشف خودکار زبان‌سرور

- PID از `Get-CimInstance Win32_Process` (نام `language_server.exe`) —
  یک فراخوانی PowerShell، بدون پنجرهٔ کنسول.
- **توکن CSRF** از خط فرمان همان پروسه (`--csrf_token`)، چون خودِ renderer هم
  همین را در هدر `x-codeium-csrf-token` می‌فرستد.
- **پورت‌ها** از `netstat -ano` مخصوص همان PID. پورت هر بار اجرا عوض می‌شود
  (`2182` → `1061/1062`) پس هیچ‌جا هاردکد نشده.
- کاندیدها با یک RPC ارزان (`GetMendelFlags`) **پروب** می‌شوند تا پورت/اسکیمای
  درست انتخاب شود؛ اولین کاندیدی که `200` بدهد برنده است.

### ۳.۲ سرور دو بار گوش می‌دهد: HTTPS و HTTP ساده

| پورت | پروتکل واقعی | HTTP ساده روی آن | HTTPS |
| --- | --- | --- | --- |
| `1061` | HTTPS | `400` (رد می‌کند) | `200` |
| `1062` | **HTTP ساده** | **`200`** | اتصال برقرار نمی‌شود |

کارهای همان سرویس روی هر دو پورت جواب می‌دهد (`ready` + ترنسکریپت کامل تست
شد). موتور اول HTTP ساده را امتحان می‌کند و HTTPS را به‌عنوان fallback نگه
می‌دارد؛ علت: دست‌دادن TLS به گواهی self-signed محلی روی این ماشین کند است و
دلیل دیگری برای پرداخت آن وجود ندارد.

### ۳.۳ آن ~۱۳ ثانیه، تقصیر ما (یا TLS) نیست

عدد اصلی، مستقل از کلاینت:

```
curl.exe  POST http://127.0.0.1:1062/…/StreamAudioTranscription  با توکن معتبر
          time_starttransfer = 13.34s   (سشن ۲: 13.32s، سشن ۳: 13.03s، سشن ۴: 13.76s)
curl.exe  همان درخواست با توکن *نامعتبر*  →  0.011s  (سرور فوراً رد می‌کند)
```

یعنی **خودِ زبان‌سرور** برای هر سشن تازه ~۱۳ ثانیه وقت می‌گذارد تا استریم را
باز کند (اتصال/احراز با بک‌اند ابری)، و بعد از آن همه‌چیز سریع است
(`ready` در ~۲۰۰ms، پارشیال‌ها زنده، متن نهایی ~۱s بعد از `EndAudioSession`).

این دقیقاً همان چیزی است که خود اپ Antigravity هم تجربه می‌کند: در ضبط جلسهٔ ۱،
فاصلهٔ «شروع استریم» تا «اولین chunk» ۱۲.۵۹۸s و ۱۴.۲۲۹s بود (سند تحلیل ۲ بند ۳).
پس این یک **تأخیر سشن در سمت سرور** است، نه رگرسیون این پیاده‌سازی — و به همین
دلیل `ready_timeout_secs` پیش‌فرض ۳۰ است، نه ۸.

### ۳.۴ `cascadeId`

- `cascadeId` **شناسهٔ محاورهٔ باز** در اپ است (`…/c/<uuid>` در URL تب).
- مقدار خالی یا ساختگی **گاهی** پذیرفته می‌شود و گاهی سشن بی‌صدا باز نمی‌شود
  (در ۲۷ سپتامبر با `cascadeId` خالی، سشن تا ۳۰s هیچ پاسخی نداد).
- پس موتور به‌ترتیب: مقدار `config` → **خواندن از پنجرهٔ باز** (پورت CDP از
  `%APPDATA%\Antigravity\DevToolsActivePort` و بعد `GET /json/list`) → یک UUID
  تصادفی. مسیر کشف با تست زنده تأیید شد.

## ۴. تأیید انتها-به-انتها (بدون میکروفون)

تست زنده با **صدای سینتِزشدهٔ ویندوز (SAPI)** — یعنی کل زنجیره بدون نیاز به
حرف زدن کاربر قابل بررسی است:

```bash
cd v-2/voice-ptt
cargo test --test antigravity_live -- --ignored --nocapture
```

خروجی واقعی این ماشین:

```
INFO  antigravity language server ready pid=22068 port=1062 scheme="http"
INFO  using the cascade id of the open Antigravity window cascade_id=b4c34916-…
INFO  antigravity transcription complete headers_ms=13034 ready_ms=13035
      sent_ms=13865 total_ms=20061 chunks=101 chars=52
antigravity transcript (20062 ms): Hello world, this is a test of the dictation bridge.
```

(۱۰۱ chunk = ۴٫۰۳ ثانیه صدا؛ متن نهایی **دقیقاً** همان جمله‌ای است که SAPI گفت.)

## ۵. چطور تست کنی (پکیج `voice-ptt-dist`)

1. Antigravity را باز نگه دار، داخل یک پروژه/محاوره (پنجرهٔ بازِ آن هم برای
   خواندن `cascadeId` استفاده می‌شود).
2. `voice-ptt-dist\voice-ptt.exe` را اجرا کن (نسخهٔ ریلیز ۲۷ سپتامبر).
3. داشبورد → تب **موتورها** → «Antigravity Live Dictation» را انتخاب کن؛
   وضعیتش باید `آماده` باشد (اگر Antigravity بسته باشد: `خطا` و در حالت
   خودکار به موتور بعدی می‌رود).
4. Notepad را باز کن، **CapsLock را نگه دار**، فارسی بگو، رها کن.
5. انتظار: ~۱۳ ثانیه سکوت (باز شدن سشن سمت سرور)، سپس متن فارسی تایپ می‌شود.
   در همان فاصله، در نوار وضعیت داشبورد، **متن در حال شکل‌گیری** دیده می‌شود.

نکته: اگر می‌خواهی مسیر بدون Antigravity هم آزمایش شود، موتور محلی whisper
همیشه به‌عنوان fallback آخر باقی است.

## ۶. محدودیت‌ها و قدم بعدی

1. **۱۳ ثانیه تأخیر باز شدن سشن** (سمت سرور). دو راه واقعی برای پنهان‌کردنش:
   (الف) باز کردن سشن در **لحظهٔ فشردن کلید** به‌جای رها کردن؛ (ب) نگه‌داشتن یک
   سشن گرم همیشه‌باز و فرستادن chunkهای سکوت برای زنده نگه‌داشتنش — که
   «دیکتهٔ زندهٔ کامل» می‌شود ولی منطق مرزِ جمله‌ها را پیچیده می‌کند.
2. **پارشیال‌ها** فعلاً در نوار وضعیت داشبورد دیده می‌شوند، نه در کپسول شناور
   (کپسول ۱۲۶×۳۲ پیکسل است).
3. **وابستگی به اپ و حساب کاربر:** بدون Antigravity در حال اجرا و لاگین،
   موتور Ready نمی‌شود؛ پروتکل غیررسمی است و آپدیت اپ می‌تواند عوضش کند؛
   مرز شرایط استفاده هم دارد (بحث در `Antigravity-Log-Analysis-01.md` بند ۶).
4. `pending`: پکیج نصب (Inno) برای این تغییر بازسازی نشده است؛ فقط exe ریلیز
   به `voice-ptt-dist` کپی شده.
