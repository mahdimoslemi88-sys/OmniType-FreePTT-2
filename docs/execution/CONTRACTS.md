# قراردادهای مشترک (K0)

بسته: `K0` · موج ۰ · تاریخ: ۲۰۲۶-۱۰-۰۱ · مالک: هماهنگ‌کننده
مبنای ورودی: [B0-orb-baseline.md](B0-orb-baseline.md) · [T0-text-baseline.md](T0-text-baseline.md) ·
[S0-session-baseline.md](S0-session-baseline.md)

این سند **قانون مشترک** موج‌های بعدی است. تا وقتی اینجا نوشته نشده، ایجنت‌ها نباید نسخهٔ
خصوصی ناسازگار از یک نوع بسازند؛ اگر قرارداد نیاز به تغییر داشت، ابتدا همین سند
به‌روزرسانی و مصرف‌کنندگانِ وابسته متوقف می‌شوند.

**قاعدهٔ ثبت:** هر چیزی که امروز در کد نیست با «پیشنهاد» علامت خورده، نه با «وجود».
ستون «وضعیت» می‌گوید کدام.

## ۱. جلسه و قطعه

**وضعیت: وجود ندارد.** `SessionDriver` فقط دو پرچم دارد ([session.rs:182](../../voice-ptt/src/state/session.rs#L182)).
رابط کاربری «جلسه» را از لبهٔ `AppState::Recording` حدس می‌زند
([overlay.rs:1024](../../voice-ptt/src/gui/overlay.rs#L1024))، که نه در بوت، نه در لغو، نه
در پاسخ دیررس معنا دارد.

```rust
pub struct SessionId(pub u64);          // یکتا در فرایند، از ۱ شروع می‌شود
pub struct ChunkId(pub u32);           // درون یک جلسه، از ۱، بدون وقفه

pub enum SessionKind { PushToTalk, LatchedHandsFree, Chunked }

/// چرخهٔ عمر. **پایانِ ضبط، پایانِ جلسه نیست.**
///
/// این تفکیک یک اشتباه را خنثی می‌کند: اگر «بسته‌شدن جلسه» را با «رهاکردن میکروفون» یکی
/// بگیریم، متنِ قطعهٔ پایانی که طبق تعریف بعد از رهاکردن میکروفون آماده می‌شود، «دیررسِ
/// جلسهٔ بسته» قلم می‌خورد و **خروجی طبیعی هر دیکته رد می‌شود**.
pub enum SessionPhase {
    /// میکروفون باز است.
    Recording,
    /// ضبط تمام شده، نتیجهٔ قطعهٔ پایانی هنوز نیامده. پاسخ‌های این فاز **معتبرند**.
    AwaitingResult,
    /// نتیجه رسید و درج انجام شد (یا عمداً انجام نشد و دلیلش ثبت شد).
    Completed,
    /// کاربر لغو کرد؛ هیچ متنی از این جلسه درج نمی‌شود.
    Cancelled,
}
```

قواعد:

1. جلسه با `Effect::BeginRecording` **ساخته** و در همان‌جا `Recording` می‌شود؛ شناسه در
   همان لحظه تخصیص می‌یابد.
2. **خروج از `Recording` ≠ بستن جلسه.** `take_and_stop` فقط میکروفون را می‌بندد و جلسه
   به `AwaitingResult` می‌رود. جلسه فقط در سه حالت بسته می‌شود: نتیجهٔ قطعهٔ پایانی رسید
   (`Completed`)، کاربر لغو کرد (`Cancelled`)، یا جلسهٔ تازه‌ای شروع شد و این یکی دیگر
   معنی ندارد.
3. پاسخِ جلسهٔ `Cancelled` یا `Completed` **درج نمی‌شود** و نتیجهٔ آن
   `NotAttempted { reason: LateForCancelledSession | LateForCompletedSession }` است.
   پاسخِ `AwaitingResult` **باید** درج شود — این مسیر عادی است، نه استثنا.
4. هر `emit` باید `(SessionId, ChunkId)` را حمل کند و مصرف‌کننده باید پیش از تزریق
   `phase` را بخواند؛ یعنی بررسی در مرز درج است، نه در تولیدکننده.
5. شمارهٔ قطعه در طول جلسه یکنواخت بالا می‌رود؛ اگر قطعه‌ای شکست خورد، شمارهٔ مصرف‌شده
   و پرواز مجدد ساخته می‌شود تا ترتیب متن نشکند.
6. `ChunkId` بدون `SessionId` هرگز در API ظاهر نمی‌شود.
7. **دو جلسهٔ هم‌زمان:** اگر کاربر پیش از رسیدن نتیجهٔ جلسهٔ اول، دوباره ضبط را شروع
   کند، جلسهٔ اول `AwaitingResult` می‌ماند و **متنش گم نمی‌شود** — ولی **ترتیب درج به زمان
   رسیدن پاسخ وابسته نیست**. نتیجه‌ها در صفی با کلید `(ترتیب شروع جلسه، شمارهٔ قطعه)`
   می‌نشینند و هر نتیجه تا نوبتش صبر می‌کند؛ نتیجه‌ای که زودتر برسد صف را دور نمی‌زند.
   پیش از درج هر متن، مقصد دوباره اعتبارسنجی می‌شود؛ اگر مقصد یا محل درج نامطمئن بود،
   متن **برای اقدام کاربر می‌ماند** و نتیجه `NotAttempted(TargetInvalid)` است.
   عبارت «حفظ متن اولویت دارد» مجوز درج خارج از ترتیب نیست؛ فقط یعنی متن در صف منتظر
   می‌ماند، نه اینکه راهتش را دور بزند.

مصرف‌کنندگان: `S1` (تولیدکننده) → `T2`، `V1`، `R1` (مصرف‌کننده). **باید پیش از موج ۲
موجود باشد.**

## ۲. مقصد

**وضعیت: وجود ندارد.** در کل `src/` هیچ `GetForegroundWindow` یا `GetWindowThreadProcessId`
نیست.

```rust
pub struct TargetIdentity {
    pub hwnd: isize,
    pub pid: u32,
    pub exe_path: Option<std::path::PathBuf>,
    pub title_at_capture: String,
}

pub enum TargetValidity {
    /// همان پنجره، همان برنامه.
    Valid,
    /// فوکوس جابه‌جا شده یا پنجره عوض شده ⇒ متن درج نشود.
    Changed,
    /// قابل‌تعیین نبود (مثلاً پنجره بسته شده) ⇒ متن درج نشود.
    Unknown,
}

pub fn capture_target() -> Result<TargetIdentity>;
pub fn validate_target(id: &TargetIdentity) -> TargetValidity;
```

قواعد:

1. مقصد در `BeginRecording` ثبت و **پیش از هر درج** دوباره اعتبارسنجی می‌شود.
2. `Changed` یا `Unknown` ⇒ متن نگه داشته می‌شود (`NotAttempted`) و تمرکز **خودکار**
   جابه‌جا نمی‌شود.
3. **`HWND` تضمین کادر متن نیست.** این در [window_shape.rs:249](../../voice-ptt/src/gui/window_shape.rs#L249)
   با ارجاع به مستندات winit مستند است و در `P1` هم تکرار می‌شود: یک پنجره می‌تواند چند
   کادر قابل‌تایپ داشته باشد (مرورگر، Word، ترمینال).
4. **تصمیم کاربر (۲۰۲۶-۱۰-۰۱): نسخهٔ نخست همان پنجره و همان فرایند را بررسی می‌کند و
   محدودیتش را صریح به کاربر می‌گوید.** جابه‌جایی میان دو کادر در یک پنجره تشخیص داده
   نمی‌شود و این یک آگاهیِ پذیرفته‌شده است، نه نقص پنهان.
5. هویت برنامه برای پروفایل از `exe_path` می‌آید، نه از عنوان پنجره.

مصرف‌کنندگان: `T2` (می‌سازد) → `V1`, `R1`, `P1`, `U1`. **باید پیش از موج ۲ موجود باشد.**

## ۳. درج

**وضعیت: دو حالت.** `EmitOutcome` الان سه حالت دارد
([machine.rs:82](../../voice-ptt/src/state/machine.rs#L82)) و `flush` می‌تواند وسط کار خطا
بدهد ([injector.rs:128](../../voice-ptt/src/output/injector.rs#L128)).

```rust
pub struct InjectRequest {
    pub session: SessionId,
    pub chunk: ChunkId,
    pub target: TargetIdentity,
    pub text: String,
    pub backspaces: u32,        // فقط برای آرتیفکتِ خودِ seam
}

/// یک‌دست: هر چیزی که می‌تواند برای یک درج بگوید، دقیقاً یکی از این چهار حالت است.
///
/// «درج ناقص» و «شکست پس از درج بخشی» **یک چیز** هستند و در `Partial` با هم می‌آیند؛
/// قرار دادنِ حالتِ نیمه‌کاره زیر `Failed` (که معنایش «هیچ‌چیز نرفت» است) گزارش را
/// خلاف واقع می‌کرد.
pub enum InjectOutcome {
    /// همهٔ نویسه‌ها تحویل شد.
    Complete { chars: u32 },
    /// بخشی تحویل شد و بعد خطا خورد؛ `typed_chars` واقعاً رفته است.
    Partial { typed_chars: u32, remaining: usize, failure: InjectFailure },
    /// تلاش شد و **هیچ‌چیز** درج نشد.
    Failed { reason: InjectFailure },
    /// اصلاً تلاش نشد؛ علت بیرون از تزریق است.
    NotAttempted { reason: NotAttemptedReason },
}

pub enum InjectFailure {
    /// `SendInput` کمتر از رویدادهای ارسالی را تحویل گرفت (برنامهٔ دیگری ورودی را
    /// می‌بلعد) — این حالت ممکن است **پس از** بخشی از متن رخ دهد.
    Blocked,
    Encoding,
    DeviceLost,
}

/// چرا اصلاً کلیدی زده نشد. این‌ها خطای درج نیستند و نباید با آن‌ها یکی شوند.
pub enum NotAttemptedReason {
    /// جلسه پیش از آماده‌شدن متن لغو شد.
    LateForCancelledSession,
    /// نتیجهٔ دیررسِ جلسه‌ای که پیش‌تر تکمیل شده بود.
    LateForCompletedSession,
    /// مقصد تغییر کرده یا قابل‌تعیین نبود.
    TargetInvalid,
    /// متن خالی بود؛ `SendInput` اصلاً صدا زده نمی‌شود.
    TextEmpty,
}
```

قواعد:

1. **درج ناقص هرگز به‌طور خودکار تکرار نمی‌شود.** تکرار کامل، متن تکراری می‌سازد. پیش‌فرض
   نگه‌داشتن همان قطعه برای اقدام کاربر است.
2. بک‌اسپیس فقط برای آرتیفکتی مجاز است که خودِ اپ در همین جلسه ساخته (`≤ MAX_BACKSPACES`
   که امروز ۲۴ است). هرگز برای متن کاربر.
3. نتیجه باید قابل‌گزارش باشد: «ناقص» یعنی ناقص، نه «موفق».
4. خالی ⇒ بدون فراخوانی `SendInput`.

مصرف‌کنندگان: `T2` (می‌سازد) → `V1`, `R1`, `U1`.

## ۴. مرز متن

**وضعیت: وجود ندارد.** `inject_text` دقیقاً همان رشته را می‌نویسد؛ هیچ سیاستی برای
«ادامه»، «خط جدید» یا «ترمیم انتها» نیست.

```rust
pub enum Boundary { Continue, NewLine, Paragraph, AfterPunctuation }

pub struct BoundaryPolicy {
    /// جداکنندهٔ میان دو قطعهٔ پشت‌سرهم در همان مقصد.
    pub between_chunks: Boundary,
    /// ترمیم انتهای قطعهٔ قبلی (مثلاً برداشتن فاصلهٔ اضافه) — فقط اگر حافظه معتبر باشد.
    pub repair_tail: bool,
}

pub struct BoundaryMemory {
    pub target: TargetIdentity,
    pub last_text_tail: String,
    pub last_edit_was_ours: bool,
}
```

قواعد:

1. پیش‌فرض نسخهٔ نخست: ادامهٔ قطعه‌ها در همان مقصد با **یک فاصلهٔ معمولی**.
2. خط جدید و نشانه‌گذاری استثنای صریح‌اند، نه پیش‌فرض.
3. **حافظهٔ مرز با تغییر مقصد یا ویرایش قابل‌تشخیص باطل می‌شود.** از حافظهٔ «آخرین متن»
   نمی‌شود وضعیت واقعی سند را بعد از ویرایش دستی استنتاج کرد — پس چنین ادعایی نمی‌شود.
4. قطعهٔ خالی هیچ‌چیز درج نمی‌کند (امروز هم می‌کند: `TypePlan::Skip`).

مصرف‌کنندگان: `T2` (می‌سازد)، `C1` (خط جدید در فرمان گفتاری از همین سیاست استفاده می‌کند).

## ۵. پردازش

**وضعیت: یک حالت ثابت.** `process_text` همیشه نرمال می‌کند و همیشه واژه‌نامه را اعمال
می‌کند ([processing/mod.rs:14](../../voice-ptt/src/processing/mod.rs#L14))؛ هیچ کلید
تنظیماتی برای آن وجود ندارد.

```rust
pub enum ProcessingMode { Raw, Conservative, Formal }

pub struct ProcessingOptions {
    pub mode: ProcessingMode,
    pub numbers: NumberStyle,        // Keep | Persian
    pub zwnj: bool,
    pub punctuation: bool,
    pub dictionary: bool,
    pub commands: bool,              // پیش‌فرض خاموش
}
```

قواعد:

1. **`Raw` واقعاً خام است**: نه نگارش، نه واژه‌نامه، نه فرمان. سیاست مرز درج مستقل
   می‌ماند و در `Raw` هم اعمال می‌شود.
2. `Conservative`: نگاشت نویسه‌های عربی، فاصلهٔ تکراری، نشانه‌گذاری؛ **نیم‌فاصله فقط در
   الگوهای معتبر** — نه با بزرگ‌کردن فهرست استثنا (شکستِ اندازه‌گیری‌شدهٔ «کلمات»، «تمام»،
   «میکروفون» در [T0](T0-text-baseline.md) بند ۴ از همین‌جاست).
3. `Formal` در موج ۵ و با کلید قابل‌خاموش‌کردن برای هر گروه قاعده.
4. گزینه‌ها در **شروع جلسه** تثبیت می‌شوند؛ تعویض وسط جلسه قواعد قطعه‌های همان جلسه را
   عوض نمی‌کند.
5. فرمان گفتاری پیش‌فرض **خاموش** است.

### تصمیم‌های قطعی کاربر (۲۰۲۶-۱۰-۰۱) — دیگر باز نیستند

| مورد | تصمیم | دلیل ثبت‌شده |
|---|---|---|
| `می روم` با فاصلهٔ صریح | فاصله حفظ می‌شود؛ نیم‌فاصله ساخته نمی‌شود | تا وقتی قاعدهٔ معتبر نداریم، اصلاح خودکار دوباره کلمهٔ سالم را می‌شکند |
| همزهٔ تنها (`مسأله`) | **حفظ می‌شود** | حذفش برای هیچ مشکل فعلی لازم نیست و متن را عوض می‌کند |
| ارقام لاتین | **پیش‌فرض حفظ**؛ تبدیل به فارسی یک گزینهٔ مستقل است | عدد در کد، شناسه یا متن انگلیسی نباید ناخواسته عوض شود |

این سه یعنی: `Normalizer` نباید «همزهٔ تنها» را حذف کند، نباید ارقام لاتین را لمس کند، و
نباید فاصلهٔ صریح را به نیم‌فاصله تبدیل کند. هر سه با نمونه‌های `UNDECIDED` در
[fixtures](T0-text-baseline.md) قفل می‌شوند.

مصرف‌کنندگان: `T1` (می‌سازد) → `P2`, `D1`, `C1`, `P1`.

## ۶. پیش‌نویس

**وضعیت: وجود ندارد.** کارت رونوشت `SHOW_TRANSCRIPT_CARD = false` است و تاریخچه فقط
در حافظه است ([S0](S0-session-baseline.md) بند ۷).

```rust
pub struct DraftId(pub u64);
pub struct DraftRevision(pub u32);

pub enum DraftStatus { Pending, Approved, Injected, Incomplete, Cancelled }

pub struct Draft {
    pub id: DraftId,
    pub session: SessionId,
    pub revision: DraftRevision,
    pub target: Option<TargetIdentity>,
    pub chunks: Vec<(ChunkId, String)>,
    pub status: DraftStatus,
}
```

قواعد:

1. در حالت بازبینی، **هیچ متنی پیش از تأیید درج نمی‌شود**.
2. ویرایش کاربر نسخه را بالا می‌برد؛ تأیید با نسخهٔ دیده‌شده انجام می‌شود.
3. **تأیید دوباره همان درخواست درج دوباره نمی‌کند** (idempotent).
4. شکست یا درج ناقص، پیش‌نویس را نگه می‌دارد و `NotAttempted` نشان می‌دهد.
5. بازکردن پنل، نگه‌داشتن مقصد را از بین نمی‌برد؛ هنگام تأیید از قرارداد مقصد معتبر
   استفاده می‌شود.

مصرف‌کنندگان: `V1` (می‌سازد) → `U1`, `D1`, `R1`.

## ۷. وضعیت اُرب

**وضعیت: موجود.** `AppState → OrbMode` در [overlay.rs:60](../../voice-ptt/src/gui/overlay.rs#L60).
هندسه از [B0](B0-orb-baseline.md) مشتق شده و تست دارد.

افزودهٔ لازم برای `O2`:

```rust
pub struct IdleClock;      // ساعت تزریقی، تا تست بدون sleep کار کند
pub enum ReturnBlocker { Recording, Processing, Dragging, Interacting, PendingDraft }
pub fn may_return(idle_secs: f32, blockers: &[ReturnBlocker], corner: Corner) -> bool;
```

قاعدهٔ اصلی: هر دورهٔ بی‌کاری **فقط یک بار** بازگشت را انجام می‌دهد و تعامل مهلت را از نو
شروع می‌کند. برش نمایشگر مقصد باید مقصد را به نمایشگر در دسترس منتقل کند.

مصرف‌کنندگان: `O2` (می‌سازد) → `O1` (اتصال به هندسه).

## ۸. اعتبارنامه

**وضعیت: وجود ندارد.** کلید سرویس در تنظیمات نگه داشته می‌شود (یا در
[doctor.rs](../../voice-ptt/src/doctor.rs) گزارش می‌شود) و هیچ مخزن امنی ندارد.

```rust
pub trait CredentialStore {
    fn save(&self, key: &str, secret: &str) -> anyhow::Result<()>;
    fn load(&self, key: &str) -> anyhow::Result<String>;
    fn delete(&self, key: &str) -> anyhow::Result<()>;
}
```

قواعد:

1. تنظیمات فقط **شناسهٔ** کلید را نگه می‌دارند، نه خودِ کلید.
2. لاگ، گزارش تشخیصی و خروجی تنظیمات هرگز کلید را نشان نمی‌دهند. (**این باید با
   تست بررسی شود، نه با قول** — امروز `--doctor` متن پیکربندی را می‌نویسد.)
3. مهاجرت مرحله‌ای: اول ذخیره و بازیابی تأیید شود، بعد کلید از فایل عمومی حذف شود.
4. شکست مهاجرت نباید اتصال کاربر را بی‌توضیح قطع کند.
5. این ادعای حفاظت در برابر همهٔ فرایندهای حساب کاربر نیست — باید در متن رابط گفته شود.

مصرف‌کنندگان: `A1` (می‌سازد) → اتصال `I2`.

## ۹. بازیابی — فقط متن، نه صدا

**وضعیت: وجود ندارد.** امروز شکست تبدیل فقط لاگ می‌شود و قطعه از دست می‌رود.

### تصمیم قطعی کاربر (۲۰۲۶-۱۰-۰۱): صدا نگه داشته نمی‌شود

1. **بافر صوتی برای انجامِ همان ضبط و تبدیلِ جاری لازم است** و بافرِ موقتِ آن با پایانِ
   همان عملیات کنار می‌رود. آنچه ممنوع است، **بافرِ صوتی برای بازیابی** است.

   شاهدِ امروزی، با دقت: `SessionBuffers.audio` یک `Vec<f32>` محلیِ همان حلقه است
   ([session.rs:297](../../voice-ptt/src/state/session.rs#L297))، نه میدانی روی
   `StateMachine`؛ `take_and_stop` با `std::mem::take` آن را **منتقل** می‌کند (پس پشت‌سرش
   یک `Vec` خالی می‌ماند، نه داده‌ای که حذف شده باشد) و `finalize(audio)` آن را مصرف
   و رها می‌کند ([machine.rs:548](../../voice-ptt/src/state/machine.rs#L548))؛
   `discard_recording` در لغو، بافرِ حلقه را خالی می‌کند
   ([machine.rs:323](../../voice-ptt/src/state/machine.rs#L323)).

   یعنی: `mem::take` **حذف نیست، انتقال مالکیت است**؛ شاهدِ نبودِ نگه‌داری، نبودِ هر میدان،
   هر فایل و هر مجموعه‌ای است که صوت را **فراتر از همان فراخوانی** نگه دارد — و جست‌وجوی
   `src/` چنین چیزی ندارد. این قرارداد آن وضعیت را **قفل می‌کند** تا موج ۴ آن را نسازد.
2. **هیچ بافر صوتی برای بازیابی، فایل صوتی یا آرشیو صوتی وجود ندارد و ساخته نمی‌شود.**
3. اگر **تبدیل** شکست بخورد، کاربر باید دوباره صحبت کند. این باید در رابط گفته شود،
   نه اینکه پنهان بماند.
4. اگر **تبدیل موفق و درج شکست بخورد**، همان متن برای اقدام مجدد نگه داشته می‌شود —
   چون متن، دادهٔ کاربر است و درج دوباره‌اش بی‌خطر است.
5. انتقال به موتور دیگر **در این نسخه معنا ندارد**، چون بدون صدای نگه‌داشته‌شده نمی‌توان
   دوباره تبدیل کرد. این قابلیت حذف شد، نه به تعویق.

```rust
/// واحد بازیابی: **متنِ آماده‌شده‌ای که درجش شکست خورده**، نه صدای خام.
pub struct PendingInsert {
    pub session: SessionId,
    pub chunk: ChunkId,
    pub text: String,
    pub backspaces: u32,
    pub attempts: u32,
    pub last_failure: InjectFailure,
}

pub enum RecoveryOutcome { RetrySucceeded, RetryFailed, Discarded, Expired, NotApplicable }
```

قواعد:

1. تلاش مجدد **فقط درج** را تکرار می‌کند، هرگز تبدیل را. متن آماده یک‌بار تولید و تا
   درج موفق یا انقضا نگه داشته می‌شود.
2. **درج ناقص (`Partial`) خودکار تکرار نمی‌شود**؛ چون بخشی از متن رفته و تکرار کامل
   متن تکراری می‌سازد. کاربر باید آگاهانه تصمیم بگیرد.
3. قطعهٔ درج‌شده هرگز تکرار نمی‌شود؛ شناسهٔ `(SessionId, ChunkId)` همان مرجع یکتاست.
4. ترتیب متن حفظ می‌شود؛ اگر قطعهٔ ۳ زودتر از ۲ آماده شد، تا رسیدن ۲ نگه داشته می‌شود یا
   وضعیت «منتظر» صریح نشان داده می‌شود.
5. نگه‌داشتن متن پیش‌فرض **در حافظه** است. اگر نگه‌داشتن روی دیسک خواسته شود، تصمیم
   جداگانه و صریح لازم دارد — در این سند فرض نشده است.

مصرف‌کنندگان: `R1` (می‌سازد) → `V1`, `U1`. **بازیابی صوتی دیگر بستهٔ جداگانه ندارد.**

## ۱۰. قواعد حاکم بر تغییر این سند

1. هر تغییر قرارداد = یک بند جدید با **تاریخ** و دلیل، و توقف موقت مصرف‌کنندگان وابسته.
2. قراردادی که در کد نیست، «پیشنهاد» است تا وقتی امضای تولیدکننده‌اش ثبت شود.
3. یک قرارداد، دو نسخه ندارد. اگر مصرف‌کننده نسخهٔ خودش را ساخت، آن نسخه خطاست.
4. ادعای «پیاده شد» فقط با تست و ارجاع به امضا. وجودِ ماژول، تحویل محصول نیست.
