# ممیزی نصب‌کننده — ۲۰۲۶-۱۰-۰۶

هر ادعای این سند یا اندازه‌گیری شده، یا از کدِ درخت خوانده شده است. جایی که چیزی آزموده
**نشده** باقرار صریح آمده.

## ۱. دو نصب‌کننده با دو AppId — یکی حذف شد

| | قدیمی (حذف‌شده) | فعلی (تنها منبع) |
|---|---|---|
| مسیر | `installer/installer.iss` | `voice-ptt/installer/omnitype.iss` |
| ساخت | `ISCC.exe installer.iss` (دستی، دستور در README) | `bash voice-ptt/installer/build-installer.sh` |
| نسخه | `0.3.0` **hardcode** در فایل | از `Cargo.toml` خوانده و **پیش از ISCC** با regex راستی‌آزمایی می‌شود |
| AppId | `D4A7B8E1-3C9F-4E62-9B5D-7A1C2F8E4B60` | `6B1F4C2A-9D3E-4A57-8C11-2F0E7B5D9041` |
| payload | exe + `DirectML.dll` + `assets\silero_vad.onnx` + `dictionary.toml` + صفحهٔ انتخاب مدل در ویزارد | **فقط `voice-ptt.exe`**؛ بقیه در اولین اجرا |
| خروجی | `installer/Output/OmniType-FreePTT-0.3.0-setup.exe` | `voice-ptt/installer/Output/OmniType-FreePTT-<ver>-setup.exe` |

چرا AppId مهم است: نصب‌کنندهٔ ویندوز نصبِ موجود را از روی `AppId` می‌شناسد. دو AppId یعنی
**دو خط نصبِ مستقل** که هیچ‌کدام خودِ دیگری را نمی‌بینند.

### شاهد روی همین سیستم

```text
%LOCALAPPDATA%\Programs\OmniType FreePTT\
  unins000.dat / unins000.exe   ۲۰۲۶-۰۹-۳۰   ← نصبِ از راه اسکریپت قدیمی
  unins001.dat / unins001.exe   ۲۰۲۶-۱۰-۰۵   ← نصبِ از راه اسکریپت فعلی

HKCU\...\Uninstall:
  "OmniType FreePTT"                    ← AppId جدید
  "OmniType FreePTT version 0.3.0"      ← AppId قدیمی
```

هر دو آنتری به **یک پوشه** اشاره می‌کنند. یعنی حذفِ یکی، فایل‌های نصبِ دیگری را جمع نمی‌کند و
کاربر دو «حذف برنامه» برای یک برنامه می‌بیند.

### کاری که شد

- `installer/` با کل محتوایش حذف شد (شامل `Output/OmniType-FreePTT-0.3.0-setup.exe` که
  `gitignore` بود و در ریپو نبود).
- [README.md](../README.md) به `build-installer.sh` وصل شد و بخش «چه چیزی نصب می‌شود» با
  payload واقعی بازنویسی شد.
- [INDEX.md](INDEX.md) ساختار ریپو و مسیر `Output` را به‌روز کرد.
- `docs/HANDOFF.md` (تحویلِ تاریخ‌دارِ فازهای قدیمی) دست‌نخورده ماند: سندِ تحویلِ گذشته است،
  نه راهنمای امروز.

**کاری که نشد:** آنتریِ `0.3.0` روی ماشین‌هایی که نصبِ قدیمی دارند باقی می‌ماند — رفعِ آن
دست‌زدن به رجیستریِ کاربر است و در محدودهٔ این ممیزی نیست. راهنمای دستی در بخش ۴.

## ۲. باگ حذفِ نصب — پاک شدن `dictionary.toml` (اندازه‌گیری‌شده)

### قانونِ خطا

`voice-ptt/installer/omnitype.iss`، پیش از اصلاح:

```ini
[UninstallDelete]
; ... کامنتِ بالای همان خط می‌گفت هرگز دادهٔ کاربر پاک نمی‌شود ...
Type: filesandordirs; Name: "{app}"
```

`filesandordirs` روی `{app}` یعنی «کل پوشهٔ نصب را حذف کن» — **شامل فایل‌هایی که ستاپ هرگز
ننوشته است.**

چرا فایلِ کاربر آنجاست: `resolve_file` در [src/paths.rs](../voice-ptt/src/paths.rs) ترتیب
`exe dir → cwd → %APPDATA%` را دارد و برای فایلِ تازه، اگر پوشهٔ exe قابل‌نوشتن باشد همان‌جا
می‌سازد. پوشهٔ نصبِ per-user قابل‌نوشتن است، پس:

| فایل | روی یک نصبِ معمولی |
|---|---|
| `dictionary.toml` | کنار exe — قواعد اصلاحِ واژه‌های کاربر، قابل‌دانلود **نیست** |
| `config.toml` | کنار exe در نصبِ تازه؛ در `%APPDATA%` اگر از قبل آنجا باشد |
| `models\`، `assets\` | کنار exe — قابل‌دانلودند |

شاهدِ زنده روی همین سیستم: `%LOCALAPPDATA%\Programs\OmniType FreePTT\dictionary.toml`
(۱۷٬۹۳۷ بایت، ۲۰۲۶-۱۰-۰۳) در همان `{app}` است.

### اندازه‌گیری

یک نصب‌کنندهٔ آزمایشی با همان قانون ساخته شد (AppId مجزا، پوشهٔ مجزا در `Temp`)، نصبِ بی‌صدا
انجام شد، یک `dictionary.toml` که ستاپ ننوشته بود کاشته شد، و حذفِ نصبِ بی‌صدا زده شد:

```text
┌─ با قانونِ قدیمی (Name: "{app}") ────────────────────────────────┐
│ قبل:  dictionary.toml  models\  payload.txt  unins000.*          │
│ بعد:  No such file or directory    ← کل پوشه رفت                │
└──────────────────────────────────────────────────────────────────┘
┌─ با قانونِ اصلاح‌شدهٔ ۰.۶.۱ (Name: "{app}\models") ─────────────┐
│ قبل:  dictionary.toml  models\  payload.txt  unins000.*          │
│ بعد:  dictionary.toml   ← ماند                                   │
│         models\ رفت · payload.txt (نصب‌شده) رفت · unins رفت      │
└──────────────────────────────────────────────────────────────────┘
```

یعنی هم تشخیص درست بود هم رفعِ آن؛ هر دو با اجرای واقعیِ نصب/حذفِ بی‌صدا، نه با خواندنِ مستندات.

### دامنه

- **بد اثر:** ۰.۴.۰، ۰.۵.۰، ۰.۶.۰ (هر سه با همان قانون منتشر شدند).
- **رفع:** ۰.۶.۱ — قانون فقط `models\` را پاک می‌کند (۱٫۷GB قابل‌دانلود)، و بقیه را خودِ
  Inno از سرِ فهرستِ چیزهایی که خودش نوشته جمع می‌کند.
- **ادعاهای غلطِ منتشرشده:** یادداشت‌های ۰.۴.۰، ۰.۵.۰ و ۰.۶.۰ هر سه می‌گفتند «حذف نصب
  فایل‌های شما را پاک نمی‌کند». هر سه **تصحیح و دوباره منتشر شدند** (`gh release edit`)، و
  README هم به‌روز شد.
- **کامنتِ خودِ فایل** هم غلط بود («Config, dictionary, models … live in %AppData%») —
  به‌روز شد، چون همین تصورِ غلط بود که قانونِ خطا را پنهان نگه داشته بود.

## ۴. آنچه باقی مانده

1. **نصبِ ۰.۶.۱ روی این سیستم انجام نشده.** نسخهٔ نصب‌شده ۰.۴.۰ است و هنگام این ممیزی در حال
   اجرا بود (قفل تک‌نسخه بین هر دو مشترک است). پس رفتارِ حذفِ نصبِ **خودِ فایلِ ۰.۶.۱** با
   آزمونِ معادلِ آزمایشی اندازه‌گیری شده، نه با اجرای خودِ آن فایل. این همان چیزی است که
   «تأیید کامل» نمی‌شود.
2. **دو آنتریِ حذف روی ماشین‌های قدیمی.** اگر «OmniType FreePTT version 0.3.0» را می‌بینید،
   نصبِ خطِ قدیمی است: آن را حذف کنید (فایل‌هایتان را نگه می‌دارد، چون آن نصب‌کننده
   `UninstallDelete` روی `{app}` نداشت) و بعد ۰.۶.۱ را نصب کنید، تا یک آنتری بیشتر نماند.
3. **مسیر آفلاین از دست رفت.** اسکریپت قدیمی در ویزارد مدل دانلود می‌کرد و `assets` و
   `dictionary.toml` را می‌بست؛ اسکریپت فعلی فقط exe می‌گذارد و اولین اجرا اینترنت می‌خواهد.
   اگر نصبِ آفلاین خواستهٔ محصول است، باید دوباره تصمیم گرفته شود — بازگرداندنِ آن **کارِ
   بعدی است، نه بخشِ این ممیزی**.
4. **پوشهٔ `models` در `voice-ptt-dist` خالی است** (۰ بایت). پس «`voice-ptt-dist` را کپی کن تا
   آفلاین داشته باشی» همیشه درست نیست: VAD و دیکشنری هستند، مدل whisper نه. README حالا این را
   صریح می‌گوید.
